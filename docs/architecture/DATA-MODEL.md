# Logical Data Model

| Field | Value |
|---|---|
| Phase | 1 (design) — tables are created by Flyway in the phase that implements each module |
| Database | PostgreSQL 16+ (platform DB). Keycloak uses its **own** database; Vault uses its own storage. |

## 1. Conventions (normative)

1. **One PostgreSQL schema per Core module** (`organization`, `identity`, `authorization`, `policy`, `risk`, `sod`, `target`, `provider`, `account`, `secrets`, `request`, `approval`, `session`, `operation`, `notification`, `audit`, `reporting`). Cross-schema foreign keys are allowed only toward modules the owning module may depend on (MODULE-BOUNDARIES.md); otherwise references are by ID without FK.
2. Primary keys: `id uuid` (UUIDv7 generated by the application). Natural keys get `UNIQUE` constraints.
3. Standard columns: `created_at timestamptz not null`, `created_by uuid`, `updated_at timestamptz not null`, `updated_by uuid`, `version bigint not null` (optimistic locking), `archived_at timestamptz` for soft-deletable aggregates.
4. Enumerations stored as `text` with `CHECK` constraints (portable, migration-friendly) — not PostgreSQL enum types.
5. Timestamps always `timestamptz` in UTC.
6. **No secret values in any table.** Columns holding Vault references are named `*_secret_ref` and contain `vault:<mount>/<path>#<version>`.
7. JSONB only for genuinely open-ended data (provider response metadata, policy conditions, capability snapshots) — never for fields used in authorization filters, which must be real columns with indexes.
8. Every foreign key column is indexed; list queries have supporting composite indexes (org unit + status, target + status, etc.).
9. Migrations: Flyway, forward-only, `V<yyyyMMddHHmm>__<module>_<description>.sql` from Phase 2 onward (V1 is the baseline); expand-and-contract for breaking changes; no `DROP`/`TRUNCATE` of data-bearing objects without an approved data-migration ADR.
10. Database roles: `iam_owner` (migrations only), `iam_app` (DML on module schemas; **INSERT/SELECT only** on `audit`), `iam_readonly` (reporting). The application never connects as owner.

## 2. Tables by schema (key columns)

### organization
- `organization (id, code UNIQUE, name, …)`
- `org_unit (id, organization_id FK, parent_id FK NULL, kind CHECK in (BUSINESS_UNIT, DEPARTMENT, TEAM), code, name, path ltree/text, …)` — `UNIQUE(organization_id, code)`, index on `path`.
- `position (id, organization_id, code, title)` · `location (id, organization_id, code, name, country, timezone)`

### identity
- `person (id, organization_id, employee_id UNIQUE NULL, given_name, family_name, display_name, org_unit_id, position_id, location_id, manager_person_id FK NULL, employment_status, start_date, end_date, email, phone, metadata jsonb)` — `CHECK(end_date IS NULL OR end_date >= start_date)`.
- `identity (id, person_id FK, type CHECK(8 types), username UNIQUE, lifecycle_state CHECK, valid_from, valid_until, risk_level, …)` — `CHECK(type NOT IN ('EMERGENCY','TEMPORARY','CONTRACTOR','EXTERNAL') OR valid_until IS NOT NULL)`.
- `platform_user (id, identity_id UNIQUE FK, keycloak_subject UNIQUE, last_login_at, mfa_enrolled boolean)`

### authorization
- `permission (code PK, resource, action, description, sensitive boolean)`
- `role (id, code UNIQUE, name, built_in boolean, description)` · `role_permission (role_id, permission_code) PK both`
- `role_assignment (id, identity_id, role_id, scope_id, source, valid_from, valid_until, granted_by_request_id NULL)`
- `scope (id, kind, is_global boolean)` · `scope_element (scope_id, element_type CHECK in (ORG_UNIT, ORG_UNIT_TREE, ENVIRONMENT, PROVIDER_TYPE, PROVIDER_INSTANCE, TARGET, TARGET_GROUP), element_value)`

### policy / risk / sod
- `policy (id, key, version, status CHECK in (DRAFT, PUBLISHED, RETIRED), applies_to jsonb, conditions jsonb, effect, obligations jsonb, published_at, published_by)` — `UNIQUE(key, version)`; trigger prevents updates to PUBLISHED rows.
- `policy_set_version (id, hash UNIQUE, activated_at, policy_ids uuid[])`
- `risk_model (id, version UNIQUE, factors jsonb, thresholds jsonb, status)`
- `sod_rule (id, code UNIQUE, left_set jsonb, right_set jsonb, mode, severity, enabled)` · `sod_exception (id, rule_id, identity_id, reason, valid_until, approval_case_id)`

### target / provider
- `target (id, name, hostname, ip inet, dns_name, type, platform, os, environment, criticality, classification, owner_identity_id, technical_owner_identity_id, business_owner_identity_id, location_id, status, discovery_state, reconciliation_state, health, tags text[])` — indexes on `(type, environment)`, `hostname`, GIN on `tags`.
- `target_provider_binding (target_id, provider_instance_id, channel)` · `dependency (id, from_target_id, to_target_id, type)` · `license_contract (id, product, vendor, license_ref, contract_ref, expires_on, support_status, owner_identity_id, renewal_date)`
- `provider_instance (id, type, name UNIQUE, version, endpoint, config jsonb /* no secrets */, credential_secret_ref, enabled, health, circuit_state, last_health_at, failure_reason)`
- `capability_snapshot (target_id, capability, status CHECK in (SUPPORTED, UNSUPPORTED, UNAVAILABLE, DEGRADED, AGENT_REQUIRED), reason, since)` PK `(target_id, capability)`
- `agent (id, host, target_id, version, os, status CHECK(8 states), certificate_serial, capabilities text[], policy_bundle_version, last_seen_at)` · `gateway (id, channel, instance_id UNIQUE, version, certificate_serial, health, last_seen_at)`

### account / secrets
- `account (id, target_id FK, native_id, name, account_type, usage, privilege_class, risk_class, owner_identity_id, linked_identity_id, governance_state CHECK, native_status, source, last_seen_at, last_used_at, credential_expires_at)` — `UNIQUE(target_id, native_id)`; indexes `(governance_state)`, `(linked_identity_id)`, `(owner_identity_id)`.
- `managed_account (account_id PK/FK, credential_policy jsonb, rotation_schedule, checkout_policy, dual_control boolean, emergency boolean)`
- `entitlement (id, target_id, native_id, type, name, privilege_level)` — `UNIQUE(target_id, native_id)` · `entitlement_assignment (account_id, entitlement_id, desired_state, actual_state, last_reconciled_at)`
- `credential (id, managed_account_id, type CHECK in (PASSWORD, SSH_KEY, API_KEY, TOKEN, CERTIFICATE, PRIVATE_KEY), secret_ref, current_version, pending_version, rotation_state, expires_at, owner_identity_id)`
- `reveal_record (id, credential_id, identity_id, justification, request_id, policy_decision_id, revealed_at, expires_at)` · `dual_control_release (id, credential_id, initiator_id, second_approver_id, state, …)`

### request / approval / session
- `access_request (id, requester_id, beneficiary_id, target_id, account_id, entitlement_id, privilege, channel, duration, justification, emergency, state CHECK(11 states), risk_snapshot jsonb, policy_decision_id, sod_result jsonb, submitted_at, …)`
- `approval_workflow (id, key, version, definition jsonb, status)` · `approval_case (id, request_id UNIQUE, workflow_id, state)` · `approval_step (id, case_id, ordinal, quorum, state)` · `approval_decision (id, step_id, approver_id, decision, comment, acr, amr text[], decided_at)` — no UPDATE after insert (trigger).
- `access_grant (id, request_id, identity_id, account_id, target_id, channel, not_before, not_after, obligations jsonb, status)` — index `(identity_id, status, not_after)`.
- `session (id, grant_id, identity_id, target_id, account_id, channel, gateway_id, source_ip inet, state, recording_state, policy_snapshot jsonb, started_at, ended_at, termination_reason)`
- `session_recording (id, session_id, object_uri, sha256, size_bytes, sealed_at, retention_until)` · `command_event (id, session_id, seq, command, action, result, at)` · `file_transfer_event (…)`

### operation / notification
- `operation (id, type, provider_instance_id, target_id, account_id, requester_id, request_id, queue, status CHECK(8 states), progress, attempt, max_attempts, deadline, started_at, finished_at, idempotency_key UNIQUE, correlation_id, error_code, error_message, provider_response jsonb /* redacted */, verification jsonb)`
- `outbox_message (id, aggregate_type, aggregate_id, destination, routing_key, payload jsonb, headers jsonb, created_at, published_at NULL, attempts)` — partial index `WHERE published_at IS NULL`.
- `processed_message (consumer, message_id, processed_at)` PK both — idempotent consumers.
- `notification_template (…)` · `notification (id, channel, recipient, template_key, payload jsonb, status, attempts)`

### audit
- `audit_event (id, partition_key, seq, occurred_at, actor_identity_id, actor_type, action, object_type, object_id, target_id, source, result, reason, request_id, correlation_id, ip inet, session_id, provider_instance_id, details jsonb, prev_hash bytea, hash bytea, schema_version)` — `UNIQUE(partition_key, seq)`; range-partitioned by month on `occurred_at`; BEFORE UPDATE/DELETE trigger raises exception; `iam_app` has INSERT/SELECT only.
- `audit_checkpoint (id, partition_key, from_seq, to_seq, root_hash, signature, key_version, created_at)`
- `evidence_link (id, from_type, from_id, to_type, to_id, relation, created_at)` — indexes on both ends.
